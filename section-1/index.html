  • 1.01 Identify the best practices of an MLOps strategy

    Best Practices of an MLOps Strategy

    MLOps (Machine Learning Operations) is a set of practices that aims to deploy and maintain machine learning models in production reliably and efficiently. It combines ML, DevOps, and data engineering best practices.

    • Version Control: Use Git or similar tools for code, data, and model versioning. Track all changes for reproducibility.
    • Automated Testing: Implement unit, integration, and data validation tests for ML code and pipelines.
    • Continuous Integration/Continuous Deployment (CI/CD): Automate the build, test, and deployment of ML models using CI/CD pipelines (e.g., Azure DevOps, GitHub Actions).
    • Experiment Tracking: Use tools like MLflow to log parameters, metrics, and artifacts for each experiment.
    • Model Registry: Register models in a central registry (e.g., MLflow Model Registry, Unity Catalog) for lifecycle management.
    • Reproducibility: Ensure that experiments and results can be reproduced by tracking code, data, environment, and random seeds.
    • Monitoring: Monitor model performance, data drift, and system health in production. Set up alerts for anomalies.
    • Collaboration: Foster collaboration between data scientists, engineers, and business stakeholders using shared tools and documentation.
    • Security & Compliance: Protect data and models, manage access, and ensure compliance with regulations (e.g., GDPR, HIPAA).
    • Rollback & Recovery: Have strategies for rolling back to previous model versions and recovering from failures.

    Example MLOps Workflow in Databricks

    1. Develop and test models in collaborative notebooks.
    2. Track experiments and results with MLflow.
    3. Register the best model in Unity Catalog or MLflow Model Registry.
    4. Deploy the model using batch, real-time, or streaming endpoints.
    5. Monitor model performance and retrain as needed.

    Practice Question

    Which of the following is NOT a best practice in MLOps?

    • A. Tracking experiments and model versions
    • B. Manual deployment of models without automation
    • C. Monitoring model performance in production
    • D. Using CI/CD pipelines for model deployment
    Show Answer

    Answer: B. Manual deployment of models without automation is not a best practice. Automation ensures reliability and repeatability.

  • 1.02 Identify the advantages of using ML runtimes

    Advantages of Using ML Runtimes

    ML runtimes are pre-configured environments optimized for machine learning workloads. In Databricks, ML runtimes include popular ML/DL libraries, GPU support, and integrations for experiment tracking and model management.

    • Ready-to-use Environments: No need to manually install or configure ML libraries (e.g., scikit-learn, TensorFlow, PyTorch, XGBoost).
    • Optimized Performance: Libraries and drivers are tuned for distributed computing and GPU acceleration.
    • Consistency: Ensures all team members use the same environment, reducing “works on my machine” issues.
    • Security & Compliance: Regularly updated with security patches and compliance features.
    • Integration: Built-in support for MLflow, Feature Store, and Unity Catalog for seamless experiment tracking and model management.
    • Scalability: Easily scale compute resources for large datasets and distributed training.
    • Support for AutoML: ML runtimes are required for using Databricks AutoML features.

    Example

    When you select a Databricks ML Runtime for your cluster, you get immediate access to all major ML libraries and tools, saving setup time and reducing errors.

    • C. It only supports basic Python scripts
    • D. It does not support distributed training
    Show Answer

    Answer: B. ML Runtimes provide a pre-configured environment with optimized libraries for ML workloads.

  • 1.03 Identify how AutoML facilitates model/feature selection.

    How AutoML Facilitates Model/Feature Selection

    AutoML (Automated Machine Learning) automates the process of model and feature selection, making it easier and faster to build high-quality models.

    • Automated Model Selection: AutoML tests multiple algorithms (e.g., logistic regression, random forest, XGBoost) and selects the best-performing one based on evaluation metrics.
    • Feature Engineering: Automatically creates, transforms, and selects features that improve model performance.
    • Hyperparameter Tuning: Searches for the best hyperparameters for each algorithm.
    • Data Preprocessing: Handles missing values, encoding, scaling, and outlier detection automatically.
    • Experiment Tracking: Logs all runs, parameters, and results for easy comparison and reproducibility.
    • Model Explainability: Provides feature importance and model interpretation tools.

    Example in Databricks

    With Databricks AutoML, you can launch an AutoML experiment from the UI or with a single command. AutoML will:

    1. Analyze your dataset and problem type (classification/regression).
    2. Try multiple models and feature sets.
    3. Return the best model, code, and feature importance report.

    Practice Question

    What does AutoML do to help with feature selection?

    • A. Randomly drops features
    • B. Automatically creates and selects the most relevant features
    • C. Only uses the first column in the dataset
    • D. Ignores feature importance
    Show Answer

    Answer: B. AutoML automatically creates and selects the most relevant features for the model.

  • 1.05 Identify the benefits of creating feature store tables at the account level in Unity Catalog in Databricks vs at the workspace level

    Benefits of Creating Feature Store Tables at the Account Level in Unity Catalog vs Workspace Level

    • Centralized Management: Account-level tables are accessible across all workspaces in the account, enabling organization-wide feature sharing and governance.
    • Data Consistency: Ensures all teams use the same, validated features, reducing duplication and errors.
    • Access Control: Unity Catalog provides fine-grained access control and auditing at the account level, improving security and compliance.
    • Collaboration: Facilitates collaboration between teams and projects by making features universally available.
    • Scalability: Supports large-scale ML initiatives by allowing features to be reused and managed centrally.
    • Lineage & Governance: Track feature usage, lineage, and ownership across the organization.
    • Workspace-level tables are only available within a single workspace, limiting reuse and collaboration.

    Example

    Creating a feature table at the account level in Unity Catalog allows a data science team in one workspace to use features engineered by another team in a different workspace, with consistent access controls and audit trails.

    Practice Question

    What is a key benefit of account-level feature store tables in Unity Catalog?

    • A. Features are only available in one workspace
    • B. Features can be shared and governed across all workspaces in the account
    • C. No access control is possible
    • D. Features cannot be reused
    Show Answer

    Answer: B. Account-level tables enable sharing and governance across all workspaces in the account.
